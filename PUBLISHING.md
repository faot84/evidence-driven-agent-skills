# Publishing notes

This package is prepared for publication as a standalone GitHub repository. Review the exact contents and repository settings before the first public release, and keep publication metadata free of private account details.

## Suggested GitHub listing

- **Repository name:** evidence-driven-agent-skills
- **Description:** Reusable Codex and Claude Code skills for evidence-based reviews, debugging, honest status reports, tenant-isolation testing, safe delegation, verified backups, and non-destructive changes.
- **Topics:** agent-skills, codex, claude-code, subagents, software-audit, debugging, multi-tenant, verified-backup, testing
- **First release:** v0.1.0 after an independent user tries the examples and the owner approves publication.

## Publication checklist

1. Review README.md, all nine SKILL.md files, agents/adversarial-reviewer.md, docs/agents.md, the community files, the backup helper, tests, and the three synthetic examples for accuracy and wording.
2. Confirm that the proposed MIT license and copyright attribution match the owner's publication choice.
3. Choose the public Git author name and email intentionally. A GitHub no-reply email can avoid exposing a personal address.
4. Run the commands in README.md and inspect the staged file list. Verify that no private project material, credentials, or local paths were added. Distinguish helper test results from unmeasured agent behavior.
5. Confirm that the conduct-reporting wording in CODE_OF_CONDUCT.md matches the maintainer's available private channels, and decide the copyright holder shown in LICENSE.
6. Create the remote repository and publish only after the owner approves the exact contents and destination.
7. After creating it, enable private vulnerability reporting (Settings, Security) so SECURITY.md works, and confirm the validate workflow passes on GitHub Actions.

The repo is useful on its own; publication should not be represented as evidence of eligibility for any subscription promotion.
